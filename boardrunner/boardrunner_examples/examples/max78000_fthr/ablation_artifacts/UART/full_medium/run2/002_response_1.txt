### 1. Previous Model Failure Analysis
The primary mismatch is in `CTRL` readback: the model synthesizes the inferred read-only status bit at `0x00800000`, but the hardware trace shows the bit appears at `0x00080000`. After firmware writes `0x28C01`, hardware reads back `0x0A8C01`, while the model returns `0x0828C01`. That wrong bit position changes the control register state seen by firmware and likely prevents it from completing UART init, which explains why the emulated run never progresses to the normal `STATUS` polling / `FIFO` traffic observed on hardware.

### 2. Register Analysis
- `CTRL` (`0x40042000`, offset `0x00`)
  - Read/write control register.
  - Firmware performs RMW on it during init.
  - Observed progression:
    - `0x0`
    - `0x20000`
    - `0x20001`
    - `0x20C01`
    - write `0x28C01` then read back `0xA8C01`
  - Inference: a writable bit at `0x00008000` causes a hardware-read-only reflected/ready bit at `0x00080000`.

- `STATUS` (`0x40042004`, offset `0x04`)
  - Polled status register.
  - `0x50` = idle / TX-ready state.
  - `0x140` = RX data available state.
  - Used in runtime polling loop around FIFO access.

- `CLKDIV` (`0x40042010`, offset `0x10`)
  - Baud clock divider.
  - Written with `0x40` during init.
  - Read/write storage behavior is sufficient from trace evidence.

- `OSR` (`0x40042014`, offset `0x14`)
  - Oversampling register.
  - Written with `0x5` during init.
  - Read/write storage behavior is sufficient from trace evidence.

- `FIFO` (`0x40042020`, offset `0x20`)
  - Shared TX/RX data register.
  - Writes send bytes out (`0x0D` seen in loop).
  - Reads return received bytes (`0x48`, `0x65`, `0x6C`, `0x6C`, `0x6F` => “Hello”).
