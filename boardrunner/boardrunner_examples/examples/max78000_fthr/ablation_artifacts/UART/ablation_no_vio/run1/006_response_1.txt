### 1. Previous Model Failure Analysis
The current model’s main bug is that it treats RX-ready in `STATUS` as a one-shot, self-clearing latch that is cleared merely by reading `STATUS`. The trace instead indicates normal UART behavior: `STATUS=0x140` corresponds to unread RX data being present, and that condition should persist until firmware actually reads `FIFO`. Because the emulation clears RX-ready on the `STATUS` read, firmware can miss the receive event and never perform the `FIFO` reads seen on hardware (`'H' 'e' 'l' 'l' 'o'`), which explains why the model’s `STATUS` entropy is too low and `FIFO` is never reached.

### 2. Register Analysis
- `CTRL` (`0x00`)
  - Main UART control/config register.
  - Bit `0x1` behaves like UART enable.
  - Firmware writes progress through `0x20000 -> 0x20001 -> 0x20C01 -> 0x28C01`.
  - Readback of `0x28C01` becomes `0xA8C01`, indicating a read-only/auto-set status bit at `0x80000`.
- `STATUS` (`0x04`)
  - Polled during runtime.
  - Idle/TX-ready state is `0x50`.
  - RX-data-available state is `0x140`.
  - RX-ready must reflect unread FIFO occupancy, not be cleared by reading `STATUS`.
- `CLKDIV` (`0x10`)
  - Baud-rate divider; firmware writes `0x40`.
- `OSR` (`0x14`)
  - Oversampling register; firmware writes `0x5`.
- `FIFO` (`0x20`)
  - TX data register on write.
  - RX data register on read.
  - Hardware returns ASCII bytes `0x48, 0x65, 0x6C, 0x6C, 0x6F` (`"Hello"`).
