### 1. Previous Model Failure Analysis
The mismatches are caused by the SPI1 master model treating each `TXDR` write as “generate a whole synthetic reply and overwrite the RX FIFO,” while `SR` is derived only from `active + rx_count`. That loses transaction phase information. In the trace, hardware shows at least three distinct SPI states: idle-ready (`0x20002`), data-available (`0x22007`), and transfer-complete (`0x301F` / `0x101A`). The current model never latches completion flags and also clears/rebuilds unread RX data on subsequent `TXDR` writes, which explains why emulation returns `0xFF, 0xFF` instead of `0xFF, 0x60` and why `SR` gets stuck at `0x22007`.

### 2. Register Analysis
- **CR1 (0x00)**  
  Main control register. Trace shows firmware enabling `SPE` and then setting `CSTART`; model should treat transfer logic as active only when both are set.
- **CR2 (0x04)**  
  Low 16 bits behave like transfer size (`TSIZE=2` in trace). Hardware `SR[31:16]` reflects this in the pre-completion state (`0x20002`, `0x22007`).
- **CFG1 (0x08)**  
  Configuration register; simple RW is sufficient for this trace.
- **CFG2 (0x0C)**  
  Configuration register; simple RW is sufficient for this trace.
- **IER (0x10)**  
  Interrupt enable register; firmware does RMW on it, so normal RW behavior is needed even if no IRQ is raised.
- **SR (0x14)**  
  Hardware-owned status register. Important observed values:
  - `0x20002`: active / ready to transmit, no RX data yet
  - `0x22007`: RX data available during transfer
  - `0x301F`: transfer complete flags set while one RX byte still remains
  - `0x101A`: transfer complete flags set after RX FIFO is emptied
- **IFCR (0x18)**  
  Clear register. Reads as zero in trace; writes should clear latched completion state.
- **TXDR (0x20)**  
  Writing starts/supplies a transfer. Model must not overwrite unread RX data from an in-flight transaction.
- **RXDR (0x30)**  
  Reading pops RX data. First pop should transition the model into the “completion flags latched” phase seen in hardware.
- **CGFR (0x50)**  
  Simple RW in this trace.

static uint32_t spi1_build_sr(SPI1State *s)
{
    uint32_t sr = 0;
    uint32_t tsize = s->cr2 & 0xFFFFu;

    if (!spi1_active(s)) {
        return 0;
    }

    /* Matches observed idle-active state: 0x00020002 when CR2 low16 == 2 */
    sr |= SPI1_SR_TXP;
    sr |= (tsize << SPI1_SR_CTSIZE_SHIFT);

    /* Matches observed data-ready state: 0x00022007 when CR2 low16 == 2 */
    if (s->rx_count > 0) {
        sr |= SPI1_SR_RXP;
        sr |= SPI1_SR_DXP;
        sr |= SPI1_SR_RXPLVL_1;
    }

    return sr;
}

{
    uint32_t frames = s->cr2 & 0xFFFFu;
    uint32_t i;

    if (frames == 0) {
        frames = 1;
    }
    if (frames > SPI1_RX_FIFO_SIZE) {
        frames = SPI1_RX_FIFO_SIZE;

     * Minimal observed behavior:

     * Model that as a simple 2-byte response for command 0xD0.

        return;

static uint32_t spi1_build_sr(SPI1State *s)
{
    uint32_t sr = 0;
    uint32_t tsize = s->cr2 & 0xFFFFu;

    if (!spi1_active(s)) {
        return 0;
    }

    /*
     * Before completion is latched, hardware reflects CR2.TSIZE in SR[31:16]
     * and reports the usual ready/data-available states:
     *   0x00020002  idle-ready
     *   0x00022007  RX data available
     */
    if (!s->xfer_complete) {
        sr |= SPI1_SR_TXP;
        sr |= (tsize << SPI1_SR_CTSIZE_SHIFT);

        if (s->rx_count > 0) {
            sr |= SPI1_SR_RXP;
            sr |= SPI1_SR_DXP;
            sr |= SPI1_SR_RXPLVL_1;
        }
        return sr;
    }

    /*
     * After RX consumption begins, the trace shows completion-type flags
     * instead of CTSIZE:
     *   0x0000301F while one RX byte is still pending
     *   0x0000101A after RX FIFO becomes empty
     */

    sr |= SPI1_SR_EOT;
    sr |= SPI1_SR_TXTF;
