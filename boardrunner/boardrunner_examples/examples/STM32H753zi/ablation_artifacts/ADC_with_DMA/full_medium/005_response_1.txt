### 1. Cross-Model Failure Analysis

- **ADC2 mismatch**
  - **Root cause:** `ADC2->CR` is missing the observed power-state behavior. The hardware trace shows `CR` sometimes reading `0x20000000`, which corresponds to a persistent high bit in the ADC control register consistent with ADC deep-power-down state. The current ADC model initializes both ADC instances with `CR=0` and never gives ADC2 that state unless firmware explicitly writes it.
  - **Bug location:** `ADC/model.c`
  - **Regression risk:** Low. The fix is scoped to ADC2 initialization and CR power-state handling. ADC1 is currently passing and is left unchanged.

- **DMA1 mismatch**
  - **Root cause:** The DMA model raises an interrupt on **half-transfer** immediately. In the trace, firmware only ever sees `DMA1->LISR = 0xC00` for Stream 1, meaning **HTIF1 and TCIF1 are both already latched** by the time the ISR runs. The current model instead causes separate ISR entries with `0x400` and `0x800`, producing the alternating mismatch.
  - **Bug location:** `DMA_with_DMAMUX1/model2.c`
  - **Regression risk:** Low. DMAMUX routing remains unchanged; only HT interrupt timing is adjusted. This should not regress the currently passing `DMAMUX1`, and it aligns better with the observed DMA1 behavior.

### 2. Register Analysis

- **ADC2 `CR`**
  - Persistent control/power register.
  - Observed changing between `0x0` and `0x20000000`.
  - `0x20000000` is consistent with a deep-power-down style state bit.
  - Should not be modeled as purely zero/reset-less state.

- **DMA1 `LISR`**
  - Latched interrupt-status register.
  - For Stream 1, hardware consistently shows `0xC00` before firmware clears flags.
  - This implies **HTIF1 + TCIF1** are both set together when firmware inspects the register.

- **DMA1 `LIFCR`**
  - Write-1-to-clear flag register.
  - Firmware clears `0x400` and `0x800` separately, matching HT and TC clear operations.
  - The model’s clear behavior is fine; the problem is when the IRQ is raised.

- **DMA1 `S1CR`**
  - Stream 1 configuration register.
  - Values already match.
  - Confirms the mismatch is not stream programming, but status/IRQ timing.
