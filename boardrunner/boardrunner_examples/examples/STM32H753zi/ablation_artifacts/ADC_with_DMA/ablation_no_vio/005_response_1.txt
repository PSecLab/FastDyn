### 1. Cross-Model Failure Analysis

- **ADC1**
  - **Root cause:** `ADC/model.c`
    - `ADC_CR` readable bits are being updated **too early**. The trace shows `CR` power/config bits becoming visible one poll later (`0 -> 0x20000000`), while the model reflects them immediately.
    - `ADC_ISR` conversion status is modeled incorrectly:
      - the model sets `EOC` too eagerly on `ADSTART`
      - `EOSMP`/`EOS` are not maintained as hardware-owned conversion-status bits while a regular conversion is active
    - These combine into the observed `ISR` mismatch (`0x1001` / premature `0x100F` vs hardware-dominant `0x100B`) and the `CR` entropy mismatch.
  - **Bug file:** `ADC/model.c`
  - **Regression risk:** Low if fixed carefully. `ADC12_Common` is passing and should remain so if only per-ADC `CR/ISR` behavior is changed.

- **ADC2**
  - **Root cause:** `ADC/model.c`
    - Same `ADC_CR` issue: the hardware shows a delayed visible transition on `CR` (`0x0 -> 0x20000000`) during polling, but the model leaves it at `0x0`.
    - This is not a DMA/DMAMUX issue; the mismatch is local to ADC CR state/readback timing.
  - **Bug file:** `ADC/model.c`
  - **Regression risk:** Low. No need to touch `DMA_with_DMAMUX1/model2.c`, which is already passing.

- **DMA cross-model check**
  - `DMA1` and `DMAMUX1` are passing.
  - The ADC mismatches are explained by ADC-local register semantics, so changing DMA would risk regressions without addressing the actual cause.

### 2. Register Analysis

- **ADCx->CR**
  - Readable control/power image.
  - Trace implies visible bits such as `DEEPPWD` / `ADVREGEN` do **not** become readable immediately on write; they appear after a poll iteration.
  - Current model updates them too soon.

- **ADCx->ISR**
  - Hardware-owned status flags.
  - Dominant hardware value `0x100B` indicates:
    - `ADRDY` and `LDORDY` set
    - `EOSMP` and `EOS` set during active regular conversion flow
    - `EOC` is **not** dominantly present
  - Current model incorrectly injects `EOC` on `ADSTART` and allows the conversion-status picture to collapse to `0x1001`.

- **ADC1->CFGR**
  - Already matches in the trace.
  - Not root cause.

- **ADC12_Common->CCR**
  - Passing; do not alter common-register behavior.

static void adc_unit_apply_pending_cr(ADCUnitState *u)
{
    uint32_t visible;

    if (!u->cr_update_pending) {
        return;
    }

    visible = u->cr_pending_visible & ADC_CR_VISIBLE_MASK;
    u->regs[ADC_CR_OFFSET >> 2] =
        (u->regs[ADC_CR_OFFSET >> 2] & ~ADC_CR_VISIBLE_MASK) | visible;

    if (visible & ADC_CR_ADVREGEN) {
        u->regs[ADC_ISR_OFFSET >> 2] |= ADC_ISR_LDORDY;
    }

    if (visible & ADC_CR_DEEPPWD) {
        u->enabled = false;
        u->regular_active = false;
        u->injected_active = false;
        u->eoc_pending_once = false;
    }

    u->cr_update_pending = false;
}
