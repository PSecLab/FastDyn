### 1. Cross-Model Failure Analysis

- **ADC1**
  - **Root cause:** In `ADC/model.c`, `ISR` is modeled mostly as a dynamic function of `CR`, but the hardware behavior in the trace is more like **sticky hardware-owned status bits**:
    - `ADRDY` remains visible after enable instead of disappearing when `ADEN` later clears.
    - `EOSMP`/`EOS` appear after a regular start and persist until cleared.
    - `EOC` appears transiently (`0x100F` rare read) and then drops back to `0x100B`.
  - There is also a smaller **CFGR readback bug**: bit `0x200000` is being stored/read back once in emulation, but hardware never shows it sticking.
  - **Buggy file:** `ADC/model.c`
  - **Regression risk:** Low if fixed carefully. `ADC12_Common` is currently passing, so the common block should remain untouched.

- **ADC2**
  - **Root cause:** Also in `ADC/model.c`. `CR` power-state behavior is too weakly modeled. The trace shows `CR` transitioning from `0x0` to `0x20000000` (DEEPPWD visible), but emulation stays at `0x0`.
  - This is not a DMA/DMAMUX issue; the mismatch is local to ADC `CR` readback/state handling.
  - **Buggy file:** `ADC/model.c`
  - **Regression risk:** Low. The change stays within ADC `CR` state handling and should not affect passing DMA/DMAMUX behavior.

- **DMA1 / DMAMUX1**
  - Passing already.
  - The ADC1 mismatch visible inside the DMA ISR sequence is a **downstream symptom** of incorrect ADC status modeling, not a DMA bug.
  - **No DMA model change needed.**

---

### 2. Register Analysis

- **ADCx->ISR (0x00)**
  - Hardware-owned status register.
  - `ADRDY` and `LDORDY` behave like sticky readiness flags.
  - `EOSMP` and `EOS` appear after conversion start.
  - `EOC` is transient in the trace: appears once (`0x100F`) then later reads become `0x100B`.

- **ADCx->CR (0x08)**
  - Mixed control/command register.
  - Command bits such as `ADSTART`, `JADSTART`, `ADSTP`, `JADSTP`, `ADCAL`, `ADDIS` should not simply behave like plain RW bits.
  - Non-command power bits like `DEEPPWD` / `ADVREGEN` must read back correctly.

- **ADCx->CFGR (0x0C)**
  - Mostly RW configuration.
  - One bit corresponding to observed `0x200000` does not stick in hardware in this trace and should be masked out on write.

- **ADC12_Common->CCR**
  - Already passing; do not change.

    uint32_t cr = u->regs[ADC_CR_OFFSET >> 2];

    /* When enabled, firmware commonly expects ADRDY to be set. */
    if (cr & ADC_CR_ADEN) {
        dyn |= ADC_ISR_ADRDY;
        dyn |= ADC_ISR_LDORDY;

    /* If regulator/power bits are set, expose LDORDY as well. */

{
    hwaddr regoff = offset & ~0x3ULL;
    uint32_t *reg;
    uint32_t oldv;
    uint32_t merged;

    if (regoff >= ADC_BLOCK_SIZE) {
        return;
    }

    reg = &u->regs[regoff >> 2];
    oldv = *reg;
    merged = (oldv & ~wmask) | (value & wmask);

    switch (regoff) {
    case ADC_ISR_OFFSET:
        /*
         * ADC_ISR is modeled as W1C for stored sticky bits.
         * Dynamic synthesized bits are computed on read.
         */
        *reg = oldv & ~(value & wmask);
        break;

    case ADC_CR_OFFSET: {
        uint32_t cr = merged;

        /*
         * Simplified command semantics:
         * - ADEN latches
         * - ADDIS clears ADEN and activity
         * - ADCAL auto-completes immediately
         * - ADSTART/JADSTART create persistent "active" state but the command
         *   bits themselves auto-clear
         * - ADSTP/JADSTP stop activity and auto-clear
         */
        if (value & wmask & ADC_CR_ADDIS) {
            cr &= ~ADC_CR_ADEN;
            u->regular_active = false;
            u->injected_active = false;
        }

        if (value & wmask & ADC_CR_ADSTP) {
            u->regular_active = false;
        }

        if (value & wmask & ADC_CR_JADSTP) {
            u->injected_active = false;
        }

        if ((value & wmask & ADC_CR_ADSTART) && (cr & ADC_CR_ADEN)) {
            u->regular_active = true;
        }

        if ((value & wmask & ADC_CR_JADSTART) && (cr & ADC_CR_ADEN)) {
            u->injected_active = true;
        }

        /* One-shot command bits do not remain set. */
        cr &= ~(ADC_CR_ADDIS |

                ADC_CR_JADSTART |
                ADC_CR_ADSTP |
                ADC_CR_JADSTP |

        break;
    }

        /* Plain RW storage for all observed configuration registers. */
        *reg = merged;
        break;

{
    hwaddr regoff = offset & ~0x3ULL;
    uint32_t *reg;
    uint32_t oldv;
    uint32_t merged;

    if (regoff >= ADC_BLOCK_SIZE) {
        return;
    }

    reg = &u->regs[regoff >> 2];
    oldv = *reg;
    merged = (oldv & ~wmask) | (value & wmask);

    switch (regoff) {
    case ADC_ISR_OFFSET: {
        uint32_t clear_mask = value & wmask;

        /* ADC_ISR sticky bits are W1C. */
        *reg = oldv & ~clear_mask;

        if (clear_mask & ADC_ISR_EOC) {
            u->eoc_pending_once = false;
        }
        break;
    }

    case ADC_CR_OFFSET: {
        uint32_t cr = merged;
        uint32_t written = value & wmask;

        /*
         * Preserve persistent power/config bits, but treat control commands as
         * one-shot actions.
         */

        if (written & ADC_CR_ADEN) {
            u->regs[ADC_ISR_OFFSET >> 2] |= ADC_ISR_ADRDY | ADC_ISR_LDORDY;
        }

        if (written & ADC_CR_ADVREGEN) {
            u->regs[ADC_ISR_OFFSET >> 2] |= ADC_ISR_LDORDY;
        }

        if (written & ADC_CR_ADDIS) {
            cr &= ~ADC_CR_ADEN;
            u->regular_active = false;
            u->injected_active = false;
            u->eoc_pending_once = false;
        }

        if (written & ADC_CR_DEEPPWD) {
            cr &= ~ADC_CR_ADEN;
            u->regular_active = false;
            u->injected_active = false;
            u->eoc_pending_once = false;

            u->regular_active = false;
            u->eoc_pending_once = false;

        if (written & ADC_CR_JADSTP) {
            u->injected_active = false;
