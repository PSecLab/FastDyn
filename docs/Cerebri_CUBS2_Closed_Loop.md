# Cerebri CUBS2 FMI3 Lockstep with FastDyn

This runbook rehosts the `mr_vmu_tropic` Zephyr firmware in FastDyn/QEMU and
connects it to the current CUBS2 compiled FMI 3 Co-Simulation plant:

```text
Rumoca FMI3 C runner <-> native FastDyn bridge <-> Zenoh/TAP <-> CUBS2/QEMU
```

The upstream CUBS2 runner owns FMU generation, FMI stepping, trace collection,
flight checks, and HTML/Markdown reports. FastDyn replaces only its
`native_sim` controller transport. The per-step path is compiled code: the FMU
runs in C and the bridge runs in optimized Rust. Python is used only to launch
the processes and generate reports after the run.

The bridge forwards the fixed-layout messages generated by `synapse_fbs`:

- 64-byte `ExternalOdometryData`
- 48-byte `PwmSignalOutputsData`
- 48-byte `AttitudeCommandData`

No JSON or Python serialization occurs in the lockstep loop.

## Repositories and firmware

Use the latest CUBS2 `main` and build the hardware target:

```bash
git -C ../cerebri_cubs2 pull --ff-only

cd ../cerebri_cubs2
nix run .#west-update
CUBS2_BUILD_DIR="$PWD/build-mr_vmu_tropic-fastdyn" nix run .#build -- -p always -- \
  -DEXTRA_CONF_FILE="$(realpath ../FastDyn/tests/integration/cerebri_cubs2_fastdyn.conf)" \
  -DDTC_OVERLAY_FILE="$(realpath ../FastDyn/tests/integration/cerebri_cubs2_fastdyn.overlay)"
cd -
```

The default FastDyn config expects sibling checkouts:

```text
workspace/
  FastDyn/
  cerebri_cubs2/
  qemu/
  libhw/
  zephyr/
  modules/
```

For another layout, export paths before invoking FastDyn:

```bash
export CEREBRI_CUBS2_ROOT=/absolute/path/to/cerebri_cubs2
export CUBS2_WORKSPACE_ROOT=/absolute/path/to/its/west/workspace
export FASTDYN_QEMU_PATH=/absolute/path/to/qemu-system-arm
```

The required firmware and generated schema headers are:

```text
$CEREBRI_CUBS2_ROOT/build-mr_vmu_tropic-fastdyn/zephyr/zephyr.elf
$CEREBRI_CUBS2_ROOT/build-mr_vmu_tropic-fastdyn/_deps/synapse_fbs_c-src/include
```

## Build FastDyn

From the FastDyn checkout:

```bash
source ./setup.sh --build-qemu --build-gazebo --skip-optifuzz
make PROBE=true DEV=true LIBHW=true LIBGZ=true FLIGHT_CONTROLLERS=true DEBUG_PRINT=true

cmake -S boardrunner/boardrunner_sdk \
  -B boardrunner/boardrunner_sdk/build \
  -DFASTDYN_INCLUDE_DIR="$PWD/include" \
  -DQEMU_INCLUDE_DIR="$(dirname "$(dirname "$FASTDYN_QEMU_PATH")")/include"
cmake --build boardrunner/boardrunner_sdk/build -j
```

Apply `patches/MIMXRT1064_snvs_size.patch` to the local CMSIS SVD checkout if
it is not already applied. It prevents the incorrect SNVS range from covering
adjacent MIMXRT1064 peripherals.

```bash
git -C third_party/common/cmsis-svd-data \
  apply ../../../patches/MIMXRT1064_snvs_size.patch
```

Build or refresh the static cache after a firmware, path, or SVD change:

```bash
FASTDYN=./fastdyn-env/bin/fastdyn
CONFIG=configs/cerebri_cubs2_mr_vmu_tropic.toml
SVD=third_party/common/cmsis-svd-data

$FASTDYN static-analyze -c "$CONFIG" -s "$SVD" --force
```

## Host network

The ENET models use TAP devices `enet` and `enet2`:

```bash
sudo modprobe tun
sudo ip link add br-fastdyn type bridge 2>/dev/null || true
sudo ip addr flush dev br-fastdyn
sudo ip addr add 192.0.2.2/24 dev br-fastdyn
sudo ip link set br-fastdyn up

sudo ip tuntap add dev enet mode tap user "$USER" 2>/dev/null || true
sudo ip tuntap add dev enet2 mode tap user "$USER" 2>/dev/null || true
sudo ip link set enet master br-fastdyn
sudo ip link set enet2 master br-fastdyn
sudo ip link set enet up
sudo ip link set enet2 up
```

The firmware uses `192.0.2.1`; the upstream runner starts `zenohd` at
`udp/192.0.2.2:7447`.

## Run

One FastDyn command now starts the QEMU firmware, upstream FMI3 runner, native
transport bridge, Zenoh router, and report pipeline:

```bash
LD_LIBRARY_PATH="${CUBS2_WORKSPACE_ROOT}/libhw/out:$PWD/build:${LD_LIBRARY_PATH:-}" \
  $FASTDYN run \
    -c "$CONFIG" \
    -s "$SVD" \
    -o fastdyn_work_cerebri_cubs2_run
```

The configured FMI3 runner exits at 40 simulated seconds and FastDyn then stops
QEMU. Do not start a second SIL command and do not use the former sleeping
placeholder process.

Useful overrides are:

```bash
export CUBS2_FASTDYN_T_END=10
export CUBS2_FASTDYN_BUILD_DIR="$CEREBRI_CUBS2_ROOT/build-mr_vmu_tropic-fastdyn"
export CUBS2_FASTDYN_SIM_SPEED=1000
export CUBS2_FASTDYN_STARTUP_TIMEOUT_S=60
export CUBS2_FASTDYN_LOCATOR=udp/192.0.2.2:7447
```

`CUBS2_FASTDYN_SIM_SPEED` is only an upper pacing limit. Actual accelerated
speed is determined by QEMU execution and the round-trip controller response.
The native bridge is built once in release mode and reused until its sources or
Cargo manifest change.

## Outputs

The upstream report artifacts are colocated with the FastDyn work directory:

```text
fastdyn_work_cerebri_cubs2_run/cerebri_cubs2_fmi3/
  native-sim-summary.md
  native-sim-report.html
  native-sim-flight.csv
  native-sim-plant.csv
  native-sim-external-odometry.csv
  native-sim-pwm.csv
  native-sim-attitude-command.csv
  fmi3-runner.metrics
  fmi3-runner.log
  native-sim.log
  zenohd.log
```

The filenames retain upstream's `native-sim` prefix for compatibility even
though the controller is the FastDyn-rehosted hardware firmware.
`native-sim.log` ends with the native bridge's step count, wall time, and
steps-per-second throughput.

The CI smoke test runs the full 40-second mission and reports both lockstep
speed and total FastDyn speed (including firmware startup and report
generation):

```bash
tests/integration/cerebri_cubs2_mission_smoke.sh
```

On the validated local run, all 2,001 steps passed at 3.60x real time in the
lockstep section and 2.06x overall.

For a native baseline without FastDyn:

```bash
cd "$CEREBRI_CUBS2_ROOT"
nix run .#native-sim-sil-test -- \
  --artifacts artifacts/native-sim-baseline \
  --t-end 40
```
